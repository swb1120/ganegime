2. APK 설치와 차량 상태 설정
공식 Pleos Connect 2.1 에뮬레이터(Android 14 / API 34, x86_64, 2560×1440)에서 검증했습니다. 개발자의 PC나 로컬 서버는 필요하지 않습니다. 차량 내비 전달은 Pleos 내비 서비스가 있는 환경에서 확인하세요. 일반 휴대전화처럼 차량 상태를 읽을 수 없는 기기에서는 입력이 잠깁니다.

GitHub 저장소의 apk/장선웅_가는김에_release.apk 파일에서 원본 파일 다운로드를 선택합니다. 전체 소스는 이메일의 최종 커밋 주소에서 내려받거나, 저장소를 복제한 뒤 해당 커밋으로 이동해 확인할 수 있습니다.
명령줄 사용 시 APK가 있는 폴더에서 아래 명령을 실행하세요. <에뮬레이터 ID>는 adb devices에 표시되는 테스트 대상 ID로 바꿉니다.
adb -s <에뮬레이터 ID> install -r "장선웅_가는김에_release.apk"
adb -s <에뮬레이터 ID> shell am start --user current -n ai.ganegime.app.release/ai.ganegime.app.MainActivity
앱 목록의 ‘가는 김에’로도 실행할 수 있습니다. 패키지명은 ai.ganegime.app.release이며 개발용 앱과 별도로 설치됩니다.

첫 실행 시 차량 속도 권한을 허용합니다. Virtual Console에서 기어 Park, 속도 0을 설정하고 1초 이상 기다립니다.
Virtual Console 연결 명령:
adb -s <에뮬레이터 ID> forward tcp:8088 tcp:8088
테스트 PC의 브라우저 주소창에 127.0.0.1:8088을 입력하고 해당 화면을 열어 둡니다. 이는 에뮬레이터 차량 신호 제어용 로컬 주소이며 자료 다운로드 사이트가 아닙니다.
D, R, N단, 주행 중, 권한 없음 또는 차량 상태 확인 불가 시 입력과 내비 전송이 잠깁니다.

3. 심사용 서버 연결
‘설정 → 서버 연결 설정’을 엽니다. 첨부한 접속안내.txt에서 review-로 시작하는 접속 코드를 전체 복사해 저장합니다. ‘설정 → 연결 확인’에서 ‘클라우드 연결됨’을 확인하세요.
카카오 API 키나 서버 URL은 입력하지 않습니다. 서버 주소는 앱에 설정되어 있습니다.
심사용 코드 유효기간은 2026.12.05 23:59:59(한국시간)입니다. 이후 연장이 필요하면 제출 이메일로 회신해 주세요.

4. 실제 검색과 일정 계산
① 출발의 ‘장소 검색’에서 ‘소프트웨어드림센터’를 검색하고 주소를 확인해 선택합니다.
② 도착의 ‘장소 검색’에서 ‘양재역 공영주차장’을 검색해 선택합니다.
③ ‘도착 목표’를 현재 한국시간보다 3~4시간 뒤로 설정합니다.
④ ‘볼일 추가 → 상점 검색’에서 ‘양재역 약국’을 검색해 한 곳을 선택합니다. ‘걸리는 시간 (분)’은 10, ‘마쳐야 할 시각’은 비워 둡니다.
⑤ 볼일을 추가해 ‘양재역 편의점’을 검색하고 같은 조건으로 선택합니다.
⑥ ‘일정 계산’을 눌러 실제 장소, 방문 순서, 도착과 완료 예상시각을 확인합니다. 조회 시점과 제공사 정보는 결과 아래 ‘계산에 쓴 교통 정보’를 펼쳐 확인합니다.
⑦ 걸리는 시간을 10분에서 30분으로 바꿔 다시 계산하고 완료와 최종 도착 예상시각을 비교합니다. 교통 재조회 결과도 함께 반영됩니다.
원하는 주소와 상점으로 바꿔 시험할 수 있습니다. 결과와 이동시간은 조회 시점에 따라 달라집니다.

5. 차량 내비 전달
‘차량 내비 연결’에서 전달할 장소 순서를 확인하고 ‘내비로 보내기’를 누릅니다. ‘연결 상세’를 펼쳐 목적지와 경유 순서 확인 결과를 보고, ‘내비 화면 열기’로 내비에서도 확인합니다.
한 번에 경유지 2곳까지 전달합니다. 경유지가 더 많으면 구간을 나눕니다. 볼일을 하나 마칠 때마다 남은 일정을 다시 계산하고 전송하세요. 카카오의 이동시간과 Pleos 내비의 예상시간은 다를 수 있으므로 전달 결과는 목적지와 경유 순서로 확인합니다.

6. 미룸, 완료와 마감 여유 확인
① 볼일의 ‘마쳐야 할 시각’과 ‘도착 목표’를 충분히 뒤로 설정하고 계산합니다. 각 볼일의 마감 여유, 여유가 가장 적은 볼일과 도착 목표까지 여유를 확인합니다.
② 선택 볼일 하나의 ‘오늘 필수’를 해제하고 마감을 과거로 바꿔 다시 계산합니다. 제시되는 미루기 대안을 선택합니다. 필수 볼일은 제외하지 않습니다.
③ ‘미룬 볼일’에서 장소, 걸리는 시간, 기존 마감이 보관되는지 확인합니다.
④ 남은 볼일을 마친 상황을 시험하려면 해당 카드의 ‘이 볼일 완료 → 완료하고 다시 계산’을 누릅니다. 실제 이용 시에는 그 장소에서 볼일을 마친 뒤 눌러야 합니다. 자동 도착 판정은 아닙니다.
⑤ 완료한 장소가 새 출발지가 되고 남은 볼일만 재계산되는지 확인합니다. 마감 여유를 확인한 뒤 새 일정을 내비로 보냅니다. 기존 내비 경로는 다시 전송해야 바뀝니다.
⑥ 미룬 볼일에서 ‘다시 추가’를 누릅니다. 기존 마감이 유지되므로 필요한 경우 수정한 뒤 재계산합니다. 앱을 다시 열어도 미룸과 완료 기록이 유지됩니다. 재계산 중 통신 오류가 나도 완료 기록은 보존됩니다.
⑦ 출발 전에 기다리면 마감 여유가 줄어듭니다. 내비 전송 직전에 현재 시각으로 다시 검사하며 마감 초과나 5분이 지난 교통 결과는 재계산하도록 안내합니다.
전송 후 화면의 일정은 전송 시각 기준입니다. 차량 위치를 실시간으로 추적하지 않으며 다음 볼일 완료 시 새 시각과 교통으로 갱신합니다.

7. 비교 시연과 계산 근거
앱 상단 ‘비교 시연’은 접속 코드 없이 사용할 수 있습니다. 이동시간 최소 기준과 마감, 처리시간을 반영한 순서를 비교하고 조건을 바꿔 보세요. 정차 조건은 동일하게 적용됩니다.
고정 데이터의 자체 비교이며 특정 상용 내비 제품을 시험한 결과가 아닙니다. 실제 검색과 교통 연동은 4~5번에서 따로 확인합니다.
소스를 내려받은 뒤 README.md가 있는 저장소 최상위 폴더에서 다음 명령으로 108개 가상 조건을 재현할 수 있습니다.
node evidence/benchmark.mjs evidence/results
외부 API와 접속 코드가 필요하지 않습니다. 입력 범위와 한계는 evidence/README.md에 있습니다.

연결이 안 될 때
- 코드 오류 또는 만료: review-를 포함해 전체 복사했는지, 앞뒤 공백과 유효기간을 확인합니다.
- 클라우드 연결 실패: 에뮬레이터 인터넷 연결을 확인합니다. 계속 실패하면 제출 이메일로 발생 시각과 오류 문구를 알려 주세요. 접속 코드는 화면 캡처에 포함하지 마세요.
- 화면 잠금: 차량 속도 권한, Virtual Console 연결, P단, 속도 0을 확인합니다. 후진 카메라 화면이 열렸다면 P로 바꾸고 앱으로 돌아옵니다.
- 내비 연결 대기: 공식 Pleos 이미지와 기본 내비의 초기 설정을 확인합니다. 기본 내비가 지연되면 해당 앱을 다시 시작한 뒤 가는 김에에서 재계산하고 전송합니다.
- 모든 일정을 마치기 어려움: 마감과 도착 목표를 확인합니다. 기본 연결 시험은 볼일의 마감을 비워 두고 도착 목표를 충분히 뒤로 잡습니다. 경로 조회가 실패하면 임의의 이동시간으로 대신 계산하지 않습니다.
- 호출 제한: 잠시 후 다시 시도합니다. 제공사 API 한도나 장애로 검색과 계산이 제한될 수 있습니다.
