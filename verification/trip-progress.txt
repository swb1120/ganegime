가는 김에 0.6.5, 일정 진행과 마감 재검사
장선웅, 2026.11.13, versionCode 11

변경 사항
1. 내비로 보내기 직전에 현재 시각으로 모든 볼일과 최종 도착 마감을 재검사합니다.
   조회 이후 기다린 시간을 반영하며, 교통 조회 후 5분이 지나면 새 조회가 필요합니다.
   내비 앱 응답을 기다리는 동안에도 네이티브에서 시간 유효기간과 주차 상태를 다시 확인합니다.
2. 대안에서 미룬 볼일은 장소, 처리시간, 기존 마감, 필수/마지막 방문 설정을 보존합니다.
   '미룬 볼일'에서 복원할 수 있고, 앱을 다시 열어도 남아 있습니다. 복원 후 마감시각을 확인하세요.
3. 각 볼일의 '이 볼일 완료' → 확인을 누르면 그 장소가 새 출발지가 됩니다.
   완료한 볼일만 제외하고 남은 일정과 교통을 다시 조회합니다. 미룬 볼일은 그대로 보관합니다.
   완료 기록을 먼저 저장하므로 재계산 중 통신 오류가 나도 기록은 유지됩니다.
4. 볼일별 완료 마감 여유, 최종 도착 마감 여유, 가장 촉박한 일정을 표시합니다.
   전송 전에는 기다린 시간이 반영됩니다. 전송 후 표시는 내비 전송 시각 기준이며 실시간 차량 추적이 아닙니다.
   실제로 볼일을 완료한 뒤 다시 계산하면 새 출발 시각과 교통으로 갱신됩니다.

사용 순서
P단, 속도 0에서 상점과 완료 마감을 입력하고 일정을 계산합니다.
마감을 지킬 수 없는 선택 볼일은 대안에서 미루고, 미룬 볼일 목록을 확인합니다.
각 장소에서 실제 볼일을 마친 뒤 '이 볼일 완료'를 확인합니다.
새 출발지와 남은 일정, 마감 여유를 확인한 뒤 '내비로 보내기'를 누릅니다.
완료 확인은 수동입니다. 앱이 도착을 자동 판정하지 않습니다.
기존 내비 경로는 새 일정을 전송해야 바뀝니다. 한 번에 목적지 1곳과 경유지 2곳을 전송합니다.

검증
서명된 release APK를 Pleos Connect 2.1 / Android 14 / emulator-5554 / user 10에서 실행했습니다.
실제 클라우드 상점 검색 → 교통 계산 → 선택 볼일 보관 → 한 볼일 완료 → 남은 일정 재계산을 확인했습니다.
내비 SDK의 목적지 및 경유 순서 일치 응답을 확인했습니다.
첫 검사에서는 에뮬레이터 기본 내비 앱이 실행 지연 상태였습니다. 해당 내비 앱을 다시 시작한 뒤 전체 통합 검사를 통과했습니다.
만료된 출발 요청은 네이티브 경계에서 차단했습니다. 복원 후 화면 재로드에서도 기록이 유지됐습니다.
TripProgressTest 1건, DrivingGuardTest 2건, PrivacyRegressionTest 2건을 통과했습니다.
JS 화면 및 서버 테스트 53건: 시간 경과, 시계 역행, 통신 실패, 저장 실패, 중복 완료, 마지막 볼일 완료 등을 포함합니다.
차량 주행 잠금과 민감 위치 로그 미보관 동작도 회귀 검사했습니다.

범위
실차 검증은 하지 않았습니다. 교통은 조회 시점 추정이며 이후 정체, 주차, 대기시간 변화는 보장하지 않습니다.
영업시간은 사용자가 확인해 입력합니다. 보관 기록은 기기 내부 저장이며 앱 삭제 시 사라집니다.
서버 변경은 필요하지 않으며 기존 클라우드 연결을 사용합니다.
이번 제출 묶음은 APK, 소스, 기획서, 영상, 실행 안내를 0.6.5 기준으로 통일했습니다.
